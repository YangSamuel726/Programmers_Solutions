## [문제]

문자열 code가 주어집니다.
code를 앞에서부터 읽으면서 만약 문자가 "1"이면 mode를 바꿉니다. mode에 따라 code를 읽어가면서 문자열 ret을 만들어냅니다.

mode는 0과 1이 있으며, idx를 0 부터 code의 길이 - 1 까지 1씩 키워나가면서 code[idx]의 값에 따라 다음과 같이 행동합니다.

- mode가 0일 때
  - code[idx]가 "1"이 아니면 idx가 짝수일 때만 ret의 맨 뒤에 code[idx]를 추가합니다.
  - code[idx]가 "1"이면 mode를 0에서 1로 바꿉니다.
- mode가 1일 때
  - code[idx]가 "1"이 아니면 idx가 홀수일 때만 ret의 맨 뒤에 code[idx]를 추가합니다.
  - code[idx]가 "1"이면 mode를 1에서 0으로 바꿉니다.

문자열 code를 통해 만들어진 문자열 ret를 return 하는 solution 함수를 완성해 주세요.

단, 시작할 때 mode는 0이며, return 하려는 ret가 만약 빈 문자열이라면 대신 "EMPTY"를 return 합니다.

## [해결 코드]

```csharp
public string solution(string code)
{
    StringBuilder ret = new StringBuilder();
    bool mode = false;
    for (int idx = 0; idx < code.Length; idx++)
    {
        if(mode == false )
        {
            if(code[idx] == '1')
            {
                mode = true;
            }
            else if(idx % 2 == 0)
            {
                ret.Append(code[idx]);
            }

        }
        else
        {
            if(code[idx] == '1')
            {
                mode = false;
            }
            else if(idx % 2 == 1)
            {
                ret.Append(code[idx]);
            }
        }
    }
    if(ret.ToString() == "") return "EMPTY";
    return ret.ToString();
}
```

## [문제 해결 과정]

※ 문제를 해결하는데 어떤 사고 과정을 거쳤는지, 어떤 자료구조 알고리즘을 왜 선택했는지 등 구체적인 근거를 설명할 수 있어야 함

mode가 0과 1밖에 없다는 가정이기에 bool값으로 대체하였다. for문을 돌면서 mode 상태에 따라 다른 로직을 진행하도록 if문을 사용하였다.

`code[idx]`를 확인하여 '1'이면 모드를 바꾸고 값을 추가하지 않도록 else if로 문자를 추가하는 로직을 붙였다.

홀수 짝수 구분은 2로 나눈 나머지가 0과 1이 나오는 것을 이용하였다.

## [후기]

풀이시간 : 10분 10초

다른 사람도 비슷하게 풀었지만 mode를 분별하는 if문과 mode를 바꾸는 if문을 따로 빼서 푼 사람도 있었다. 가독성이 좋다.

```csharp
string answer = "";
bool mode = false; // false = 0 true = 1

for(int i=0; i<code.Length; i++)
{
    if(code[i] == '1')
    {
        mode = !mode;
        continue;
    }

    if(mode && i%2 == 1)
        answer += code[i];
    else if(!mode && i%2 == 0)
        answer += code[i];
}
if(answer.Length == 0)
    answer = "EMPTY";
return answer;
```

나도 `ret`의 공백 검사를 Length 검사로 바꾸면 더 좋았을 듯 하다.
