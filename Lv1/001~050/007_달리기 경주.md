## [문제]
얀에서는 매년 달리기 경주가 열립니다. 해설진들은 선수들이 자기 바로 앞의 선수를 추월할 때 추월한 선수의 이름을 부릅니다. 예를 들어 1등부터 3등까지 "mumu", "soe", "poe" 선수들이 순서대로 달리고 있을 때, 해설진이 "soe"선수를 불렀다면 2등인 "soe" 선수가 1등인 "mumu" 선수를 추월했다는 것입니다. 즉 "soe" 선수가 1등, "mumu" 선수가 2등으로 바뀝니다.

선수들의 이름이 1등부터 현재 등수 순서대로 담긴 문자열 배열 players와 해설진이 부른 이름을 담은 문자열 배열 callings가 매개변수로 주어질 때, 경주가 끝났을 때 선수들의 이름을 1등부터 등수 순서대로 배열에 담아 return 하는 solution 함수를 완성해주세요.

## [해결 코드]
```csharp
public string[] solution(string[] players, string[] callings) 
{
    Dictionary<string, int> playerRankDict = new Dictionary<string, int>();
    for(int i = 0; i < players.Length; i++)
    {
        playerRankDict.Add(players[i], i);
    }
    
    for(int c = 0; c < callings.Length; c++)
    {
        string name = callings[c];
        
        int back = playerRankDict[name];
        int front = back - 1;
        string anotherName = players[front];
        players[front] = name;
        players[back] = anotherName;
        playerRankDict[name] = front;
        playerRankDict[anotherName] = back;
    }
    return players;
}
```

데이터를 어떻게 가공하고 사용할 것인가?

### 두번째 생각 (해결 코드로 작성한 생각)
아니다. 좀 생각의 틀을 바꿔보자. 중요한건 호명한 것을 어떻게 사용할 것인가와 순서를 바꾸는데 필요한 데이터가 뭔지다. 또 앞 사람은 어떻게 찾을 것인가다.

순서를 어떤 자료구조로 구현하냐에 따라 순서를 바꾸는데 필요한 데이터가 달라진다. => 배열로 한다면
순서를 바꾸는 데 필요한 데이터는 인덱스(순서)

선수의 이름을 가지고 인덱스를 구할 수 있나? 또 그 인덱스를 변경할 수 있어야 함. => hash 기반이 가장 빠름 Dictionary

- 선수가 현재 몇 등(인덱스)인지는 string을 int로 보관하는 것이므로 Hash기반 Dictionary로 관리
- 선수의 등수는 string[]의 순서로 표시
- 앞 등수 선수 이름은 호명한 선수의 인덱스를 Dict에서 찾아 -1 한 값을 찾음

해결 순서
- 선수의 이름과 현재 등수(위치 인덱스)를 Dictionary로 저장 및 관리
- 호명 배열을 순회하며 선수들의 위치를 바꿔줌
  - 부른 선수가 몇등인지 Dict를 통해 찾고
  - 등수에 -1을 하여 앞 사람의 이름을 알아 Dict에서 등수를 갱신할 수 있도록 찾음
  - 배열에서 서로의 이름 위치를 바꾸고 Dict의 등수도 갱신 함
- 배열 반환

### 3번째 생각
목표는 최종 등수를 인덱스로 선수 이름을 string[]에 담아서 반환하는 것

(하나의 변수에 많은 정보를 압출할 수록 좋은건가?)
(아 풀기는 풀었는데 생각을 문제의 조건과 단계가 정리가 안된거면 요행으로 푼거지 거의 그냥, 연습을 해야 한다... 푼다고 끝이 아니야)

string[]에 최종 등수를 인덱스로 선수 이름을 담으려면 각 선수가 몇등인지를 알아야 한다.

각 선수가 몇등인지를 알려면 해설진 호명에 따라 초기 등수 데이터(`players`)를 가지고 등수를 옮기는 로직이 필요하다.

여기서 선택지가 둘로 나뉜다.
 - 기존 초기 등수 데이터가 반환 형식을 만족하므로 등수를 옮기는 로직으로 해당 데이터의 상태를 갱신하는 것
 - 초기 등수 데이터를 사용하기 좋은 다른 데이터로 가공하고 등수를 옮기는 로직으로 이 다른 데이터를 가공한 다음 다시 반환 형식으로 가공하는 것

<if 1>
초기 등수 데이터(배열)를 가지고 호명에 따라 등수를 옮기는 로직을 만드려면 어떤 것이 필요한가?
 - 초기 등수 데이터가 등수를 보장하고 선수들의 이름도 등수에 따라 보관하고 있음
 - 그렇다면 필요한 것이 호명한 선수가 현재 몇등인지를 아는 것이다.
 - 그러나 배열을 순회하며 해당 등수를 찾기에는 선수가 5만명이 될 수도 있기에 비용이 O(n)수준으로 올라간다. 그렇기에 이름 기반으로 등수를 빠르게 알 수 있는 방식을 사용해야 한다. => Hash기반 검색 사용
 - 앞 사람의 등수도 알아야 서로 바꾸는데 이는 호명한 사람의 등수만 알면 쉽게 계산할 수 있다.(`back - 1`) 
 - 배열의 데이터를 갱신하고 나면 이름 기반 등수 저장 데이터도 같이 갱신해주어야 차후 데이터 갱신에 올바른 영향을 줄 수 있다.

다른 데이터로 가공한다면 어떤 데이터로 가공하지?
 - 이름 기반으로 등수 저장 Dict와 등수 기반 이름 저장 Dict를 만들어 서로 데이터를 갱신하는 방식도 있겠다.
 - 연결 리스트와 Dict(string, Node)를 가지고 데이터를 갱신할 수도 있겠다.


## [후기]
풀이시간 : 22분 40초

Dict 두개로 문제를 푼 사람도 있었고, 나처럼 Dict와 배열을 가지고 문제를 푼 사람도 있었다.

앞선 방식보다 내 방식의 장점은 Dict와 Array의 접근 방식의 차이이다.
우선 호명한 이름을 등수로 바꾸기 위해 둘다 똑같이 Dictionary<string, int>를 사용하였다. 이후 등수를 이용해 앞 사람의 이름을 알아낼 때 Dict 키 접근과 배열 인덱스 접근의 차이가 발생했다.

플레이어 수가 충분히 많아질수록 Dict는 충돌처리 비용이 발생할 가능성이 높아지지만 배열은 그렇지 않다.
